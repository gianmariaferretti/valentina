## Private photograph migration

Code is ready: allowlisted signed-cookie `/api/private-media/[id]`, private bucket check, MIME/size limits, no shared caching, no public/signed Storage URLs, denied public optimizer, common failure-safe Image wrapper. Invalid IDs/path traversal never call Storage. All Map/place/Gallery/Awards/Memory/Polaroid consumers use it. The legacy `/images/travel/*` deny-only rule protects retained originals **on this new build**, not older deployments.

Configure server-only `SUPABASE_URL`, `SUPABASE_SECRET_KEY` (or legacy service-role alternative), and the existing `SUPABASE_PRIMARY_USER_ID` locally. Keep `SITE_ACCESS_CODE` and `AUTH_SECRET` unchanged for the actual site. Do not paste keys in chat. No new public environment variable is needed. Bucket name is fixed/allowlisted.

Read-only inventory (no credentials needed):

```bash
node scripts/migrate-private-media.mjs
```

After explicit approval and configuration, upload/verify only:

```bash
node --env-file=.env.local scripts/migrate-private-media.mjs --apply
```

The script targets only the existing project, creates a private bucket through the official Storage API, refuses public buckets/different existing bytes, uploads without overwriting, compares authenticated download SHA-256 with every original, and rejects anonymous public/authenticated object access. It never touches user-state tables.

To remove public sources, first run a local build with the real Storage configuration, or a separately approved deployed build. Set `VG_MIGRATION_SITE_URL` and `VG_MIGRATION_SESSION` securely in a local ignored environment file (existing signed access cookie; never print it). Then:

```bash
node --env-file=.env.local scripts/migrate-private-media.mjs --apply --verify-site --archive-public-sources
```

This requires ALL 26 authenticated application downloads to match their original hashes, anonymous application requests to return 401 and the exact no-store header. Only then are originals moved recoverably to ignored `.private-media-source-backup/`; the ignored receipt records hashes, not keys/cookies. No source deletion precedes successful verification. Review/stage the resulting tracked removals separately. Partial failures retain source files and are safe to retry. If configuration is absent, the actual upload/removal remains **BLOCKED**, regardless of passing fixture tests.

## Rules and trusted rewards

Blocks increase every 15 foods; the movement loop refuses new hazards under food/body or within two Manhattan cells of the head. Speed remains bounded, with unchanged keyboard/swipe/d-pad controls.
